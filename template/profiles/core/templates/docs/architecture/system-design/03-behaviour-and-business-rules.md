## Business rules
The "always" and "never" statements the system must obey. The ID'd catalogue lives where requirements live: global rules in `docs/product/SPEC.md` (§7), feature rules in each feature spec. List here, by ID, the rules that shape the behaviour in this document.

## Invariants
What must always remain true — even when many things happen at once (concurrency) or part of the system fails.

## Validation and constraints
Which inputs are accepted, which are rejected, and where the hard limits are.

## Preconditions and postconditions
What must be true before an operation runs, and what's guaranteed to be true after it.

## Acceptance criteria
How we'll know it's done: link each behaviour to requirement IDs and tests.
