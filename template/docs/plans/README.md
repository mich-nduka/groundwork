# Implementation Plans

One short plan per non-trivial change, written before the work starts. Plans make the change reviewable: what was intended, what it touches, and how it will be checked.

## Rules

1. Copy `_template/PLAN.md` into this directory and name the file after the change (lowercase words separated by hyphens, for example `add-sign-in.md`).
2. Name the requirement IDs — and the `CAP-` capabilities — the plan covers. Plans with no IDs are a sign the change is trivial enough not to need a plan.
3. Keep the plan current as the work changes, and note in it when the approach changes.
4. Delete a plan once its change is done, or keep it if the reasoning is worth keeping — your choice, but don't leave stale plans.
