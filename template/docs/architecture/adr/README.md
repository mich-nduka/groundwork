# Architecture Decision Records

ADRs are short records of important decisions: what was decided, why, and what follows from it.

Write one when a decision is hard or costly to reverse, affects several components, or sets a lasting constraint. Don't use ADRs for routine implementation details.

- Name files `NNNN-short-decision-title.md`.
- Lifecycle: Proposed → Accepted / Rejected → Superseded.
- Copy `0000-template.md` to start a new one.

Link the requirement IDs involved, and update the system design when an accepted decision changes the architecture.
